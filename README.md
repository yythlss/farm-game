# 🌾 AI 种田经营游戏

> 30 天，把一块薄田经营成产业。
> 规则引擎负责公平结算，大模型负责让每一天都不重样。

一个可以直接点开就玩的**农业经营小游戏**：你接手一块 9 格农田，在 30 天里播种、浇水、施肥、收割、买卖，
应对 5 种天气与**每天由大模型实时生成的随机事件**（虫害、干旱、集市涨价、商人收购、邻居求助……），
最后按总资产结算农场评级：**破产农夫 / 小康农场 / 农业大亨**。

## 一分钟上手

### 方式一：Docker 一键运行（推荐）

```bash
docker build -t ai-farm-tycoon .

# 推荐：透传 CNB 平台变量，让事件由大模型实时生成
# （只写变量名不写值，docker 会自动从当前 shell 继承，密钥不进镜像、不进命令行历史）
docker run --rm -p 8080:8686 \
  -e CNB_API_ENDPOINT -e CNB_REPO_SLUG -e CNB_TOKEN \
  ai-farm-tycoon

# 不带变量也能跑，此时事件全部由内置事件库提供
docker run --rm -p 8080:8686 ai-farm-tycoon

# 浏览器打开 http://localhost:8080
```

> 在 CNB 云原生开发环境中 `CNB_API_ENDPOINT` / `CNB_REPO_SLUG` / `CNB_TOKEN` 会被平台自动注入，
> 因此直接用 `.cnb/settings.yml` 里的「🌾 开始游戏」按钮启动时**无需任何配置**即可用上大模型。
> 启动日志会明确打印当前是否接入，例如：`▸ 大模型 : 已接入 deepseek-v3`。

### 方式二：本地直接跑

```bash
cd game
pip install -r requirements.txt
PORT=8080 python app.py        # 8080 仅为本地调试端口
# 浏览器打开 http://localhost:8080
```

> 容器内服务固定监听 `0.0.0.0:8686`；本地开发建议用 `PORT=8080` 避开 IDE 占用的端口。

### 方式三：只想验证数值平衡（无头模拟）

```bash
cd game
python tools/simulate.py                  # 三种策略各跑 200 局，输出评级分布
python tools/simulate.py --strategy smart -v --runs 1   # 单局逐日日志
```

## 玩法说明

### 每天你可以做的事

| 行动 | 消耗 | 效果 |
| --- | --- | --- |
| 播种 | 体力 1（用库存种子或花金币买种子） | 在空地种下作物 |
| 浇水 | 体力 1 | 该地块水分 +45 |
| 施肥 | 体力 2 + 12 金币 | 该地块产量系数 ×1.25，每茬限一次 |
| 收获 | 体力 1 | 成熟作物按公式结算产量入仓 |
| 买卖 | — | 随时按集市现价买种子、卖收成 |
| 休息 | — | 体力 +4 |
| 进入新的一天 | — | 天气变化、作物生长、AI 事件、体力 +6、行情刷新 |

**关键节奏**：体力每天只恢复 6 点，所以「今天浇哪几块地、种什么」本身就是资源分配决策。

### 作物

| 作物 | 种子成本 | 生长天数 | 基础产量 | 基准售价 | 天气偏好 | 定位 |
| --- | --- | --- | --- | --- | --- | --- |
| 🥕 萝卜 | 12 | 3 天 | 3 | 11 | 雨 1.30 / 晴 1.15 / 干旱 0.70 | 快速回本的开荒作物 |
| 🌾 小麦 | 30 | 5 天 | 4 | 17 | 晴 1.25 / 雨 1.05 / 干旱 0.60 | 稳产主力口粮 |
| 🌽 玉米 | 55 | 7 天 | 5 | 25 | 晴 1.30 / 雨 1.15 / 干旱 0.55 | 中周期高收益，怕旱怕冻 |
| 🎃 南瓜 | 85 | 9 天 | 7 | 30 | 寒潮 1.15 / 晴 1.10 / 干旱 0.70 | 周期最长、单产最高 |

> 开局只有 500 金币与 3 包萝卜种子，**种不起 9 块南瓜**——先靠短周期作物滚资本，再逐步升级，是核心乐趣。

### 天气

| 天气 | 水分变化/天 | 灾害概率 | 说明 |
| --- | --- | --- | --- |
| ☀️ 晴 | −10 | — | 光照充足，多数作物生长加快 |
| 🌧️ 雨 | +35 | — | 天然灌溉，水分自动回满 |
| 🔥 干旱 | −24 | 4% | 土地干裂，务必浇水 |
| ⛈️ 暴风雨 | +45 | 10% | 水分充足但有受灾风险 |
| ❄️ 寒潮 | −6 | 8% | 生长放缓，但南瓜反而喜欢 |

每天还能看到**明日预报**，可以提前布局。

### 产量公式（可讲解的核心规则）

```
产量 = 基础产量 × 天气系数 × 照料系数 × 事件系数
```

- **照料系数** = 水分系数 × 施肥系数 × 虫害系数
  - 水分系数：≥60 → 1.00；30~59 → 0.85；<30 → 0.60
  - 施肥系数：施过肥 → 1.25
  - 虫害系数：有虫害 → 0.55
- **事件系数**：由 AI 事件的 `growth_bonus` 累加到地块上，区间 `[0.5, 2.0]`

### AI 随机事件

每天进入新的一天时，后端会把**当前农田状态 + 玩家最近一次行动 + 最近日志**打包发给大模型，
要求它返回一个结构化事件（严格 JSON），玩家从 2~3 个选项中做选择：

```json
{
  "title": "蚜虫来袭",
  "description": "叶片背面爬满蚜虫，嫩芽开始卷曲。农资店老板说特效药不便宜。",
  "type": "pest",
  "effects": { "gold": 0, "energy": 0, "growth_bonus": 0, "market_modifier": {} },
  "choices": [
    { "text": "花钱买药", "cost": 60, "effect": "heal_pest" },
    { "text": "先扛一扛", "cost": 0, "effect": "crop_damage" }
  ]
}
```

事件覆盖 5 类：`weather` 天气 / `pest` 虫害 / `market` 市场 / `social` 社交 / `good` 好事，
效果会真实作用到金币、体力、生长系数与市场价格上。

### 成就与结局

| 成就 | 条件 |
| --- | --- |
| 💰 第一桶金 | 累计卖货收入达到 300 金币 |
| 👑 丰收之王 | 累计收获 60 份作物 |
| 🕳️ 破产边缘 | 金币一度跌到 20 以下 |
| 🧪 科学种田 | 累计施肥 20 次 |
| 🐛 灭虫专家 | 累计消除 3 次虫害 |
| 🏆 农业大亨 | 总资产突破 2500 金币 |

第 30 天按**总资产**（金币 + 库存收成估值 + 在地作物估值 + 种子估值）评级：

| 评级 | 门槛 |
| --- | --- |
| 🏆 农业大亨 | ≥ 3000 |
| 🌾 小康农场 | ≥ 1200 |
| 💸 破产农夫 | < 1200 |

## 这个项目把 AI 用在了哪里（核心看点）

**AI 是玩法核心，而不是装饰。** 但为了避免"大模型一抽风游戏就玩不了"，做了三层工程设计：

### 1. AI 与规则引擎彻底解耦

```
前端 (原生 JS 面板)
  └─ Flask 路由
       ├─ engine/  纯 Python 确定性规则引擎：生长、水分、虫害、结算、成就、评级
       └─ ai/      只负责产出一个符合契约的事件 JSON
```

两者唯一的交互点是 `pending_event` 这一个数据结构。**大模型完全不可用时，游戏依然能完整玩满 30 天。**

### 2. 事件契约强校验（防脏数据）

大模型返回内容必须依次通过：

1. `json.loads` → 剥离 ```` ```json ```` 代码块包裹
2. 字段补全与类型归一（`effect` 别名映射、非法枚举值兜底）
3. 数值夹取：`gold ∈ [-200, 200]`、`growth_bonus ∈ [-0.5, 0.5]`、`market_modifier 系数 ∈ [0.5, 2.0]`、选项数量 `∈ [2, 3]`
4. 任一步失败 → 整体放弃该结果，降级

**脏数据绝不进入结算。** 所有 LLM 异常都在 `ai/` 层被吞掉并转成错误字符串，接口永不因大模型而 500。

### 3. 内置事件库兜底 + 来源可见

`ai/fallback_events.py` 内置 **24 条**覆盖全部 5 类的事件模板，字段结构与 LLM 输出**完全一致**，
所以前端渲染逻辑零差异。

界面右下角「AI 事件引擎」面板实时显示 **AI 生成 / 本地兜底 的占比**，
每条日志也会标注 `AI 生成` 或 `本地兜底` 徽标——演示时可以直接讲清楚这次是模型生成还是降级。

### 4. 零密钥接入 CNB 大模型

优先读取 CNB 云原生环境自动注入的变量，无需任何 API Key：

| 变量 | 用途 |
| --- | --- |
| `CNB_API_ENDPOINT` + `CNB_REPO_SLUG` | 自动推导地址 `{endpoint}/{slug}/-/ai-ide/v2/chat/completions` |
| `CNB_TOKEN` | 作为 `Authorization: Bearer` 凭证 |
| `MODEL_ID` | 模型名，未设置时用内置默认值 `deepseek-v3` |

也支持标准 OpenAI 兼容写法覆盖：`BASE_URL` / `API_KEY` / `MODEL_ID`（或 `LLM_*`、`OPENAI_*`），
以及 `LLM_TIMEOUT` 调整超时（默认 8 秒，实测单次事件生成约 3.5 秒）。

> 该接口仅支持**流式（SSE）**响应，`ai/llm_client.py` 用标准库 `urllib` 实现并同时兼容 SSE 与普通 JSON 两种返回体。
> 全流程只用标准库，**不引入 openai SDK**，镜像更小、构建更快。

落地时踩到并已修掉的两个坑，记录在此避免复现：

1. **`model` 字段必填。** 不传并不会走服务端默认，而是直接返回
   `400 {"code":11102,"msg":"model [] service info not found"}`。
   因此代码里内置了 `DEFAULT_MODEL = "deepseek-v3"`（实测 `deepseek-v3` / `deepseek-r1` 均可用；
   选 v3 是为了避开推理模型把思维链混进正文导致 JSON 解析失败）。
2. **只有 `api.cnb.cool` 能走通大模型网关。** 平台同时注入的 `CNB_WEB_ENDPOINT`（`cnb.cool`）
   请求同一路径会返回 `400 Invalid argument`，所以推导地址时只用 `CNB_API_ENDPOINT`。

**排查提示**：`/api/meta` 的 `meta.llm` 字段返回完整接入诊断（地址来源、模型来源、缺失项，不含密钥），
页面右下角「AI 事件引擎」面板会直接显示缺失了哪些变量，启动日志也会打印同样的信息。

> 容易忽略的一点：普通本地 `docker run` **不会**继承宿主的 `CNB_*` 变量，
> 必须像上面那样显式 `-e` 透传，否则会一直走内置事件库。

### 5. 数值平衡可回归

数值平衡最容易在现场翻车，所以提供了无头模拟器，用三种玩家策略各跑 200 局验证三档评级都能覆盖：

| 策略 | 行为 | 中位数总资产 | 评级分布 |
| --- | --- | --- | --- |
| 精明型 | 择优种植 + 施肥 + 择机出售 | ≈ 3680 | 农业大亨 79.5% / 小康农场 20.5% |
| 保守型 | 只种萝卜小麦 + 稳健灌溉 | ≈ 1990 | 小康农场 99.5% |
| 摆烂型 | 只种白送的种子，基本不浇水不施肥 | ≈ 940 | 破产农夫 73.5% / 小康农场 26.5% |

**改任何数值后跑一遍 `python tools/simulate.py`，就能确认没有把游戏改成"必破产"或"躺赢"。**

## API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/` | 游戏页面 |
| `GET` | `/api/health` | 探活，返回 `{"status":"ok"}` |
| `GET` | `/api/meta` | 静态配置表（作物 / 天气 / 事件类型 / 成就 / 评级档位） |
| `POST` | `/api/new-game` | 开新一局（可传 `seed` 复现） |
| `GET` | `/api/state` | 获取完整状态（含待处理事件） |
| `POST` | `/api/action` | 执行行动：`{type: plant\|water\|fertilize\|harvest\|buy\|sell\|rest, plot?, crop?, amount?}` |
| `POST` | `/api/event/choose` | 选择事件选项：`{index: 0}` |
| `POST` | `/api/next-day` | 进入下一天（生成天气 + AI 事件 + 每日结算） |
| `GET` | `/api/rating` | 结算评级与统计 |
| `GET` | `/api/achievements` | 成就墙 |

统一响应格式：

```jsonc
// 成功
{ "ok": true, "state": { /* ... */ }, "messages": ["..."], "new_achievements": [] }
// 失败（HTTP 400/404/405/500）
{ "ok": false, "error": { "code": "bad_request", "message": "体力不足……" } }
```

## 项目结构

```
.
├── README.md                  # 本文档
├── Dockerfile                 # python:3.12-slim，非 root 运行，监听 0.0.0.0:8686
├── .cnb.yml                   # 引入中心 CI 检查 + main 推送构建镜像 + 云原生开发环境
├── .cnb/settings.yml          # 「🌾 开始游戏」一键预览按钮
└── game/                      # 应用代码
    ├── app.py                 # Flask 入口：静态托管 + 全部 API + 统一错误处理
    ├── requirements.txt       # 唯一依赖：Flask
    ├── engine/                # 规则引擎（纯 Python，无 AI 依赖）
    │   ├── config.py          #   数值配置表（作物/天气/经济/成就/评级阈值）
    │   ├── state.py           #   状态定义、初始化与序列化
    │   ├── weather.py         #   天气生成与影响
    │   ├── actions.py         #   六类玩家行动与前置校验
    │   ├── settlement.py      #   每日结算、产量公式与事件效果落地
    │   ├── achievements.py    #   成就判定
    │   └── rating.py          #   总资产与评级
    ├── ai/                    # AI 事件层
    │   ├── prompts.py         #   提示词 + 状态摘要
    │   ├── llm_client.py      #   OpenAI 兼容客户端（标准库 urllib，支持 SSE）
    │   ├── event_generator.py #   生成主流程 + 契约校验 + 降级
    │   └── fallback_events.py #   24 条内置事件库
    ├── tools/simulate.py      # 无头数值回归模拟器
    ├── templates/index.html   # 单页骨架
    └── static/css|js          # 深色数据面板风样式与交互（原生，无构建步骤）
```

前端为**单页原生 HTML/CSS/JS**，无框架、无构建步骤、无 CDN 依赖，
由 Flask 直接托管，因此在离线容器里也能完整运行。

## 界面说明

深色数据面板风仪表盘，桌面端三栏、窄屏自动堆叠：

- **顶部命令栏**：天数进度、天气胶囊与明日预报、金币 / 体力 / 总资产指标、「进入新的一天」主按钮
- **中部农田**：3×3 地块卡片，含作物形象、生长进度条、水分条、施肥/虫害/可收获角标
- **右侧栏**：集市行情（含涨跌箭头与价格变动动画）、仓库与种子（一键买卖）、AI 事件引擎统计
- **底部**：可按「AI 生成 / 本地兜底」筛选的农场日志流 + 成就墙
- **弹窗**：AI 事件（带影响预览与选项）、地块操作面板、30 天结算页
- **氛围**：天气会改变环境光与粒子层（晴天暖光晕、雨天雨丝、暴风雨闪电、寒潮飘雪），并尊重 `prefers-reduced-motion`

## 技术选型说明

- **Python 3.12 + Flask 3**：唯一第三方依赖，规则引擎全用标准库实现
- **无数据库、无缓存中间件**：单机小游戏定位，进程内单会话状态 + 可重入锁，避免为演示引入额外组件
- **前端零依赖**：不引入 Tailwind/框架/CDN，保证离线容器可用、镜像极小
- **LLM 调用用 `urllib`**：不引入 openai SDK，构建 8 秒内完成

## 已知边界

- 单进程内存态，**只支持单会话**；多人同时访问会共用同一块农田（演示场景足够）
- 使用 Flask 自带开发服务器，未上生产级 WSGI（作品定位为 Demo）
- 未配置大模型环境变量时自动降级为内置事件库，此时「AI 事件」由本地模板提供
